# 2026 시스템 프로그래밍 중간고사 테스트

출처: `중간고사_실습_1_2026.pdf` 2–6쪽. 시험 응시자 안내는 채점기 실행 지시로 취급하지 않는다.
학생 저장소에는 **`midterm/` 하나만** 있으며 다음 7개 프로그램을 파일명으로 구분한다.
각 실행은 해당 C 파일 **하나만** 컴파일한다. 문제별 학생 디렉터리를 만들거나 모든 `.c`를 함께 링크하지 않는다.

```text
학생 저장소/
  midterm/
    copy.c
    bookcreate.c
    bookquery.c
    bookupdate.c
    sortedbookquery.c
    searchbook.c
    sortedbookcreate.c
    (학생이 사용하는 헤더, db.dat 등)
```

## 케이스 구성

**필수 28개 + 진단용 추가 8개 = 총 36개**. 사용자 지정 기준에 따라 각 문제의
**배점 × 그 문제의 필수 케이스 통과 수 / 필수 케이스 수**로 부분점수를 계산한다.
전체 36개 통과 비율을 총점에 곱하지 않는다. 추가 8개는 실행·기록하되 점수에서는 제외한다.
문제별 점수는 소수 둘째 자리까지 반올림(half-up)하고 그 결과를 합산한다. 총점은 **75점**이다.
특정 파일만 선택하면 그 문제의 배점이 해당 실행의 만점이다.

예: 복사 문제의 필수 5개 중 4개 통과 → `10 × 4 / 5 = 8점`.
연도 정렬 저장의 필수 2개 중 1개 통과 → `20 × 1 / 2 = 10점`.
시험지에는 케이스별 부분점수 규칙이 없으며, 이 비례 방식은 사용자가 선택한 채점 기준이다.

| 문제 | 실행 파일 | 기본 | 추가 | 검사 내용 |
|---|---|---:|---:|---|
| 1 (10점) | `copy.c` | 5 | 0 | 기본 복사, 소문자 변환, 대문자 변환, 덮어쓰기, 원본 파일 없음 |
| 2-(1) (5점) | `bookcreate.c` | 1 | 2 | 입력한 모든 필드가 DB에 저장되고 조회되는지 |
| 2-(2) (10점) | `bookquery.c` | 2 | 2 | 전체 조회, 대출 가능 필터, 모두 가능/모두 대출 중 |
| 2-(3) (10점) | `bookupdate.c` | 9 | 1 | 대출 횟수 증가, 이미 대출 중이면 변경 없음, 반납, 연속 대출·반납, 다른 책 보존 |
| 3-(1) (10점) | `sortedbookquery.c` | 2 | 1 | 대출 횟수 내림차순, 0회, 횟수 동률 |
| 3-(2) (10점) | `searchbook.c` | 7 | 0 | 첫/중간/마지막 책, 숫자 제목, 없는 제목, 대소문자 구분, 접두사 거부 |
| 3-(3) (20점) | `sortedbookcreate.c` | 2 | 2 | 등록 후 새 조회 프로세스에서 연도 내림차순, 역순 입력, 연도 동률, 1권 |

- 복사 정상 케이스 4개: `testcase/system/midterm/<케이스>/case.json`과 보조 파일.
  기존 GUI/CLI의 `Grader` 형식을 그대로 사용한다. `target_file: copy.c`, `sources: [copy.c]`를 지정했다.
- 복사 오류 1개와 도서 시나리오 31개: 이 폴더의 `scenarios.json`.
  DB 생성 → 대상 프로그램 → 재조회가 같은 임시 복사본에서 실행된다.
- `profile.json`: 시험지에서 지정하지 않은 등록 입력 형식, DB 경로, 출력 행 파싱 등을 조정한다.
- `problems.json`: 시험지 2–6쪽의 문제 본문을 옮긴 것. Qwen 정성평가의 요구사항으로만 사용하며 실행 채점에는 쓰지 않는다.
- `src/midterm.py`: 위 두 형식의 테스트를 함께 실행하는 전용 CLI.
- `src/midterm_qualitative.py`: 정성평가용 문제 본문·DCUCode 평가 기준·시험 배점·전송 파일 범위를 만든다.

## 실행

프로젝트 루트에서 Docker Desktop과 `grader-image`를 준비한 뒤 실행한다.

```powershell
# 학생 한 명: 저장소 안 midterm을 찾음
.venv/Scripts/python.exe src/midterm.py src/origin/system_3_2026/학번

# 분반 전체: 각 학번/midterm 안의 파일을 직접 사용
.venv/Scripts/python.exe src/midterm.py src/origin/system_3_2026 --batch

# 한 프로그램만 / 선택 경계조건 포함
.venv/Scripts/python.exe src/midterm.py src/origin/system_3_2026 --batch --target bookupdate.c
.venv/Scripts/python.exe src/midterm.py src/origin/system_3_2026 --batch --include-extra

# 이미 midterm 폴더를 지정했다면
.venv/Scripts/python.exe src/midterm.py path/to/student/midterm --chapter .

# 실행 없이 대상 파일과 케이스 목록 확인
.venv/Scripts/python.exe src/midterm.py --list --include-extra
```

매 실행은 `reports/midterm/<시각_식별자>.json`에 새 결과를 저장한다.
`--output reports/원하는이름.json`으로 지정할 수도 있다. 각 단계의 실행 소스·입력·출력·종료 코드,
실제 레코드와 기대 레코드가 들어 있다. 기존 학생 파일과 DB는 수정하지 않는다.
같은 이름의 CSV에는 문제별 자동·최종 점수와 총점을 저장한다.
`passed`는 통과, `wrong_answer`는 결과 불일치, `needs_review`는 입력 형식·의존 프로그램·실행 환경 등의 검토 필요 상태이다.
대상 프로그램 자체의 컴파일 오류·시간 초과·실행 오류는 해당 필수 케이스 실패로 계산한다.
등록/조회 등 연계 프로그램이 실패해 대상 문제를 검사할 수 없으면 점수를 비운다.
지정 C 파일이 없거나 파일명 대소문자가 다르면 시험지의 파일명 조건에 따라 해당 문제는 0점이다.
학생 저장소/`midterm` 자체를 찾지 못했을 때는 수집·경로 문제와 미제출을 구분할 수 없어 점수를 비운다.
`needs_review`를 해당 문제 0점으로 자동 변환하지 않는다. 종료 코드는 전부 통과 0, 미통과/검토 필요 1, 설정/환경 오류 2이다.

## Qwen 정성평가

GUI에서 `midterm`과 문제(C 파일 또는 전체 문제)를 선택하고 학생을 고른 뒤 **Qwen 정성평가**를 열면 다음이 미리 채워진다.

- **문제 요구사항**: `problems.json`의 시험지 본문. 2번·3번의 하위 문제는 공통 요구사항·데이터 테이블을 앞에 한 번 붙인다.
  전체 문제를 선택하면 7개 문제 본문을 순서대로 합친다. 창에서 수정하거나 슬라이드 선택으로 바꿀 수 있다.
- **평가 기준 / 배점**: DCUCode의 정확성·알고리즘·가독성·문제 이해도와 자원 관리(파일·동적 메모리·프로세스) 3문항을 각각 0–10점 정수로 평가한다.
- **문제 배점 / 자원 적용**: 시험 배점은 1번 10점, 전체 75점 등으로 미리 설정된다. 각 자원은 자동/포함/제외로 지정할 수 있다.
  자동은 문제에서 요구하거나 실제 코드에서 사용하는 자원을 평가한다. 필요한 자원을 구현하지 않았어도 제외하지 않는다.
  비적용 자원은 계산에서 빼고, 적용 문항만 평균·반올림해 자원 관리 R(0–10)을 만든다.
  종합 품질은 `round((정확성+알고리즘+가독성+문제이해도+R)/50*100)`,
  시험 제안 부분점수는 `round(시험배점*(정확성+문제이해도+R)/30)`이다.
  자원이 모두 비적용이면 R을 제외하고 분모를 각각 40, 20으로 바꾼다(DCUCode 원식).
  따라서 파일만 쓰는 복사 문제는 파일 관리만 자원 점수에 반영하고, 동적 메모리·프로세스를 안 쓰면 해당 문항은 제외한다.
- **전송 파일**: 학생 `midterm/` 폴더에서 **선택한 문제의 C 파일과 `.h` 헤더만** 보낸다. `bookcreate1.c`, `fscan.c`, `db.dat`,
  실행 파일처럼 시험지에 없는 파일은 보내지 않는다. 파일명 대소문자가 다르면 시험지 조건에 따라 대상이 없는 것으로 보고
  그 학생은 **평가 실패**로 기록한다. 전체 문제에서는 7개 중 존재하는 파일만 보내되, 하나도 없으면 평가 실패다.

결과 JSON의 `context.preset`에 문제 제목과 배점, 각 행의 `sources`에 전송 파일 패턴이 남는다.
자원 적용 설정·판정 사유, 제외 항목, 종합 품질·제안 부분점수도 JSON/CSV로 보관한다.
기본 **학생별 요약 CSV**는 한 학생당 한 행이며, 항목별 점수는 열로 저장한다. 총평의 개행도 공백으로 합친다.
**항목별 상세 CSV**를 선택하면 항목별로 한 행씩 저장하고, 전체 근거를 다시 열려면 JSON을 사용한다.
결과 표의 **전체 선택 → 선택 학생 일괄 승인**으로 미확정 제안 점수를 한 번에 확정할 수 있다.
일부 학생만 선택해도 되며, 기존 확정 점수와 평가 실패는 건너뛰고 공통 검토 의견과 함께 자동 저장한다.
문제 요구사항 앞에는 사용자 보정(True/1=대출 가능, 대출 시 False/0·횟수 증가, 반납 시 True/1)을 붙여 시험지의 상충하는 예시보다 우선 적용한다.
정성평가 점수는 실행 채점 점수(`reports/case-grading/...`)와 별개의 교수자 검토용 제안이며 자동으로 합산하지 않는다.

GUI에서는 **장 `midterm`**을 선택하면 문제 목록에 **전체 문제(36개)**와 C 파일별 문제가 나타난다.
학생의 문제 디렉터리는 필요하지 않으며, 선택한 파일을 `학생/midterm/`에서 바로 실행한다.

1. 분반에서 `midterm`을 선택한다. 기본은 ‘전체 문제 · 7개 파일’이다.
2. 전체 36개를 실행하거나, `bookupdate.c` 같은 파일을 골라 해당 파일의 모든 케이스를 실행한다.
3. ‘도서 입력 형식’은 기본 `profile.json`을 사용한다. 등록 방식이나 출력 형식이 다른 제출물은 별도 JSON을 선택한다.
4. 학생을 선택하고 ‘선택 N명 일괄 채점’을 누른다. 결과는 기존 결과 표와 자동 저장 기록에 나타난다.
5. ‘상세 근거 보기’에서 파일명, 기대/실제 레코드, 등록·조회·갱신 각 단계의 입력과 출력을 확인한다.

GUI는 추가 경계조건 8개를 포함한 **36개**를 사용한다. 파일별 개수는 복사 5, 등록 3, 조회 4,
대출·반납 10, 횟수 정렬 3, 검색 7, 연도 정렬 저장 4개다.
결과 표에는 문제별 점수와 총점이 먼저 나오며 케이스 통과 수는 진단 정보로 남긴다.
‘사유’ 열에는 `1번: 출력·파일 불일치 1건 (필수 4/5 통과)`처럼 감점 근거,
연계 검사 불가 원인, 최신 수동 조정 사유를 짧게 표시한다. 긴 내용은 마우스를 올리면 전체를 볼 수 있고,
전체 사유는 JSON과 성적 CSV의 `reason`에도 저장된다. 추가 케이스 실패는 ‘점수 제외’로 구분한다.
입력 형식 또는 연계 프로그램 때문에 필수 케이스를 판정할 수 없으면 해당 문제와 총점을 ‘검토 필요’로 표시한다.
다른 문제의 계산 가능한 점수는 유지한다. 추가 케이스만 검사 불가이거나 실패한 경우에는 점수에 영향을 주지 않는다.
‘문제 점수 조정’에서 선택 학생의 문제별 최종 점수를 입력할 수 있다. 검토자와 조정 사유가 필요하며,
자동 점수·원본 케이스 판정·이전 점수와 새 점수·시각을 모두 보존한다.
GUI 자동 저장의 `run.json`에는 전체 근거와 조정 이력, `cases.csv`에는 원본 판정,
`summary.csv`에는 문제별 자동·최종 점수와 총점이 저장된다. CSV/JSON 내보내기에도 점수가 포함된다.
기존에 점수 없이 저장한 기록에는 소급 적용하지 않으며, 새로 채점한 기록부터 이 기준을 저장한다.
중지는 기존 방식대로 현재 학생의 결과를 저장한 후 적용한다. 실행 중에는 프로필을 바꿀 수 없으며,
실행에 사용한 케이스·프로필·기대 데이터는 `run.json`에 함께 저장한다.
`scenarios.json`을 일반 `case.json`이나 `problem.yaml`로 열 필요는 없다.

복사 정상 케이스만 기존 CLI로 실행하려면:

```powershell
.venv/Scripts/python.exe src/cli.py src/origin/system_3_2026 --batch --chapter midterm --cases testcase/system/midterm --output reports/midterm-copy.json
```

## 1번 문제: 활성 케이스 5개

| 케이스 | 실행 인자 | 확인 내용 |
|---|---|---|
| 기본 복사 | `0 source.txt destination.txt` | 예제 문자열 그대로 복사·화면 출력 |
| 소문자 변환 | `1 source.txt destination.txt` | `hello world goodbye`로 변환 |
| 대문자 변환 | `2 source.txt destination.txt` | `HELLO WORLD GOODBYE`로 변환 |
| 덮어쓰기 | `0 source.txt destination.txt` | 긴 기존 대상 파일을 `AbZ\n`으로 교체하고 남은 내용이 없는지 확인 |
| 원본 파일 없음 | `0 source.txt destination.txt` | 원본을 준비하지 않고 오류 메시지와 종료 확인 |

1번은 필수 5개만 실행하며 10점 배점이므로 통과 1개당 2점이다.
이전의 나머지 16개는 `enabled: false`로 보관하며 GUI·CLI 실행과 점수 계산에서 제외한다.
이미 저장된 결과에는 당시의 21개 기준이 보존된다. 새 구성을 적용하려면 다시 채점한다.

## 확정한 상태 의미와 미지정 사항

### True/1은 대출 가능, False/0은 대출 중

사용자 확인에 따라 **True/1 = 대출 가능**, **False/0 = 대출 중**으로 확정했다.
전체 테스트에서 같은 의미를 적용한다. 대출 가능 목록은 ID 2·4이며,
대출하면 횟수가 1 증가하고 상태가 False, 반납하면 횟수는 유지하고 상태가 True가 된다.
이미 False인 책에 대한 대출 요청은 횟수와 상태를 변경하지 않는다.
시험지 4쪽 상태 변경 설명은 이 기준과 반대이므로, 사용자 확인을 우선한다.

### DB 레코드와 등록 입력 형식은 자유

시험지는 필드의 자료형도 반드시 지킬 필요가 없다고 명시한다. 따라서 공통 바이너리 `db.dat`를 제공하지 않는다.
각 제출자의 `bookcreate.c`로 DB를 만들고 같은 제출자의 조회 프로그램으로 확인한다.

기본 등록 입력은 **한 줄에 ID/책명/저자/연도/대출횟수/대출유무, EOF 종료**를 가정한다.
이는 시험지의 추가 요구사항이 아니라 실행을 위한 기본 프로필이다. 입력 형식이 다른 제출물은
프로필을 복사해 조정한 뒤 `--profile 경로.json`으로 실행한다.
예를 들어 맨 앞에 책 수가 필요하면 `create_prefix`를 `"{n}\n"`, 끝에 -1이 필요하면
`create_suffix`를 `"-1\n"`로 지정한다. `record_template`은 필드 순서와 줄바꿈을 바꿀 수 있다.
`args`에는 파일명별 명령행 인자 배열을 지정할 수 있다. DB 파일 인자를 요구한다면
`"args": {"bookcreate.c": ["db.dat"], "bookquery.c": ["db.dat"]}`처럼 해당 파일들을 모두 지정한다.

기본 파서는 출력 중 `ID 책명 저자 연도 대출횟수 True/False(또는 0/1)` 행을 찾고 제목·메뉴·열 간격은 무시한다.
다른 표기/열 순서라면 `row_regex`를 추가한다. 이름 있는 그룹 `id`, `title`, `author`, `year`, `count`, `available`이 모두 필요하다.
대출가능 그룹 값은 True/False 또는 0/1을 사용한다. 오류 문구가 다르면 `error_regex`도 조정한다.

등록/조회 중 하나가 동작하지 않으면 연계 테스트만으로 결함 위치를 확정할 수 없다.
기초 등록 → 전체 조회가 기대 데이터와 다르면 후속 도서 테스트는 `needs_review`로 남긴다.
등록 문제도 조회 프로그램에 의존한다. 원시 DB 저장 순서의 판별은 시험지가 제시한 방법인
등록 후 `bookquery.c` 실행으로 확인하므로, 조회 자체가 재정렬하는 구현은 코드 검토가 추가로 필요하다.

## 입력·기대값

기본 DB 입력(`exam`, 문제 2):

```text
1 1984 George 1949 7 0
2 Luster Raven 2020 3 1
3 Hamnet Maggie 2020 0 0
4 theWish Nocholas 2021 2 1
```

`exam_q3`은 문제 3의 표에 나온 별도 스냅샷으로, Hamnet의 횟수만 1이다.
문제 2의 초기 0과 섞지 않았으며, 이 표를 특정 반납 동작의 결과라고 가정하지 않는다.

| 시나리오 | 입력/조작 | 기대값 |
|---|---|---|
| 전체 조회 | `0` | 입력한 4권의 모든 필드 일치 |
| 대출 가능 조회 | `1` | ID 2, 4 (True) |
| Luster 대출 | `0 2` | ID 2 횟수 4, 상태 False; 나머지 불변 |
| 이미 대출 중인 Hamnet 대출 | `0 3` | 횟수 0, 상태 False 그대로 |
| Hamnet 반납 | `1 3` | 횟수 0 유지, 상태 True |
| Luster 재대출 | `0 2` → `1 2` → `0 2` | 각 단계 검사, 최종 횟수 5, 상태 False |
| 중복 대출 | `0 4` → `0 4` | 횟수는 3에서 더 늘지 않음 |
| 대출 횟수 정렬 | `exam` 또는 `exam_q3` | ID 순서 1, 2, 4, 3 |
| 정확한 제목 검색 | `1984`, `Luster`, `Hamnet`, `theWish` | 해당 레코드 1개 |
| 검색 실패 | `princess`, `luster`, `Ham` | 레코드 없음 + 오류 메시지 |
| 연도 정렬 저장 | 기본 입력/역순 입력 | ID 4 → {2, 3} → 1; 같은 연도끼리 순서는 자유 |

모든 도서 조회는 레코드 전체를 비교하여 누락·중복·필드 혼동도 탐지한다.
정렬은 값의 내림차순과 레코드 보존을 함께 검사하며, 동률 순서는 고정하지 않는다.
기존 출력의 메뉴 문구, 표 열 너비, 안내 메시지까지 완전 일치하도록 강제하지 않는다.
다만 비표준 출력 형식은 프로필 조정이 필요하다.

추가 8개는 다른 데이터 입력, 전체 대출 가능/불가능, 불연속 ID, 정렬 동률, 1권 DB이다.
잘못된 옵션·없는 ID 처리, 중복 ID 정책, 빈 DB 출력, 최대 제목 길이는 시험지에서 정하지 않아 필수 채점에 추가하지 않았다.
파일 복사 오류의 메시지/종료 코드도 고정되어 있지 않아 오류 문구와 정상 종료 여부를 확인하고 특정 숫자 코드는 요구하지 않는다.

## 검증

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p test_midterm.py -v
$env:SWLAB_TEST_DOCKER = '1'
.venv/Scripts/python.exe -m unittest discover -s tests -p test_midterm.py -v
```

Docker 검증은 `tests/fixtures/midterm/library_fixture.h`에서 7개의 독립 C 프로그램을 한 폴더에 구성하여
36개 전체 케이스를 실행한다. 이 fixture는 채점기 확인용 합성 데이터/구현이며 교수자 기준 답안이나 학생 코드 검증 결과가 아니다.
회귀 테스트는 원본 DB 보존, 대출 횟수 누락 탐지, 대소문자 무시 검색 탐지, 정렬 방향과 동률도 확인한다.
`tests/test_midterm_gui.py`는 GUI의 전체/파일별 선택, 복수 학생 채점, 중첩 레코드 상세 보기,
‘검토 필요’ 표시, 기록 다시 열기, 직접 실행의 단일 파일 컴파일을 확인한다.
Docker 활성화 시 GUI 버튼을 통해 36개 케이스 전체를 실행하고 원본 DB 보존도 확인한다.
