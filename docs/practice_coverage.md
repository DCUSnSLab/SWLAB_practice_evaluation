# 실습 자료와 채점 범위

제공 폴더의 25개 PPT, 519쪽을 `practice_catalog.json`에 색인했다. 각 항목은 원본 경로, 장 번호, 페이지, 텍스트를 보존한다. 슬라이드에 포함된 실행 결과 이미지·코드 이미지의 OCR 결과는 포함하지 않으며, GUI의 원본 열기로 확인한다. 설치 안내 PDF는 문제 카탈로그 대상이 아니다.

## 추가한 케이스의 근거

- 4장 수정본 7쪽: cat은 파일 인자가 없으면 표준입력을 사용. 기대 출력은 입력 원문이다.
- 4장 수정본 9쪽: 첫 파일의 내용을 두 번째 파일에 복사. 대상 파일이 이미 존재하는 경우 이전 내용을 교체하는지 검사한다.
- 5장 수정본 11–12쪽: read/write 루프, O_TRUNC, 512바이트 버퍼보다 큰 입력 처리. 원본과 대상 파일 내용의 완전 일치를 검사한다.

`examples/cat`, `examples/copy`, `examples/copy_syscall`은 이 케이스들의 실행 검증용 구현이다. 출력 안내 문구가 허용되는 복사 문제는 stdout을 검사하지 않고 생성 파일만 검사한다. 기존 케이스는 수정하지 않았다.

## 판본 차이와 원문 오타

축소·경량·수정·full 판본의 문제 수와 번호가 다를 수 있으므로 서로 자동 병합하지 않는다. 특히 3장에는 CLI와 CLion 판본이 함께 있으며 기존 chap3 폴더가 어느 수업 판본인지 확인해야 한다.

6장 링크 삭제 지시에는 link()라고 적혀 있지만 삭제 동작과 충돌한다. 12장의 여러 실행 예시는 서로 다른 문제에 alarm.c라는 이름을 반복 사용한다. 이를 근거로 파일명이나 정답을 자동 추정하지 않는다. 강의자가 해당 수업 판본과 제출 소스명을 확인하고 case.json의 target_file/sources를 지정한다.

## 자동화의 한계

자료 전체 색인과 모든 문제의 완전 자동 채점은 다르다. 현재 기본 배포 케이스로 모든 장의 성적을 확정할 수는 없다. 기존 케이스와 위에 명시한 새 케이스만 활성화되어 있으며, 테스트가 없는 문제는 합격으로 처리하지 않는다. 수동 검토는 코드 미리보기·수동 실행·원본 PPT를 함께 사용한다. 바이너리 레코드, 파일 메타데이터, 특정 API 사용, 다중 터미널 조작은 별도 평가 기준이 필요하다.

수동 검토 결과와 판단 근거는 GUI의 `수동 평가 기록`으로 남기고 CSV/JSON으로 내보낼 수 있다. 자동 검사 합격과 수동 판정은 서로 다른 상태로 표시된다.

## Qwen 자동 생성 활용

이제 기본 배포 케이스 외의 문제도 GUI에서 해당 PPT 페이지를 선택해 케이스 초안을 일괄 생성할 수 있다. 교수자 기준 코드가 있으면 실행 결과로 기대값을 채운다. 기준 코드가 없는 경우에는 LLM이 제안한 정답이며, 강의자가 검토한 뒤 활성화한다. 잠금·시그널·소켓·가변 출력·특정 API 사용 여부의 검토 범위는 그대로 적용된다. 자동 생성 기능이 추가되어도 모든 장을 기본 설정만으로 완전 자동 판정하는 것은 아니다.
