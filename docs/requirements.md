## 판단 원칙

출력 형식이 화면 이미지에만 있는 문제, 실행 시마다 PID·시간·주소가 달라지는 문제, 터미널 조작·잠금·시그널·네트워크 실험은 고정된 output.txt를 임의로 만들어 자동 합격으로 처리하지 않는다. 강의자가 정한 추가 케이스 또는 수동 검토가 필요하다. 프로그램의 기능을 검사하는 테스트와 특정 시스템 호출을 사용했는지 검토하는 과정도 구분한다.

GitHub 명단에 포함된 실제 학생 저장소를 이번 개발 검증 목적으로 일괄 새로 수집하거나 성적을 확정하지 않았다. 제공된 원본 PPT, CSV, 기존 학생 제출물은 개발 산출물로 덮어쓰지 않았다.

| ID | 요구사항 | 수용 기준 | 구현 |

| R14 | 실습 설명 기반 생성 | PPT 판본/페이지 또는 직접 입력으로 입력·인자·보조 파일·기대값을 1–10개 생성 | ai_case_generator.py |
| R15 | 교수자 기준 코드 활용 | 제공된 코드의 복사본을 Docker에서 실행해 stdout/파일 기대값 계산, 실패를 정답으로 저장하지 않음 | llm_cases.py |
| R16 | 생성물 검토와 활성화 | 요약·JSON 편집, 비활성 초안과 검토 완료 저장 구분, 출처 기록, 기존 채점기 호환 | ai_case_generator.py |

LLM 출력은 실행 코드가 아닌 데이터 스키마로 제한한다. 허용되지 않은 실행 설정, 경로 탈출, 실행 가능한 보조 소스 파일, 중복 케이스명과 과도한 응답 크기는 거부한다. 교수자 기준 코드는 서버로 전송하지 않는다. LLM 기대값의 정확성과 모든 실습의 자동화 가능성은 별도이며 검토 메모와 수동 평가 흐름을 유지한다.

## 정성평가 추가 요구사항

| ID | 요구사항 | 수용 기준 | 구현 |
|---|---|---|---|
| R17 | 코드 기반 Qwen 정성평가 | 문제 요구사항과 소스, 수정 가능한 평가 기준으로 항목별 점수·근거·개선 의견 생성 | qualitative.py |
| R18 | 같은 문제의 학생 일괄 평가 | 학생별 독립 요청, 일부 실패 시 계속 처리, 중지 및 완료 결과 자동 저장 | qualitative_gui.py |
| R19 | 근거와 평가 상태 | 소스 파일·줄 범위 검증, 점수 범위 검증, 합계 직접 계산, 실패를 0점과 구분 | qualitative.py |
| R20 | 교수자 검토 및 보관 | AI 제안 유지, 최종 총점·검토 의견 별도 기록, CSV/JSON 저장과 JSON 재열기 | qualitative_gui.py |

정성평가 소스 코드는 사용자 지정 자체 Qwen 서버로 전송한다. 명단 파일이나 저장소 전체는 전송하지 않고 선택 문제의 지원 소스 파일에 한정한다. 평가는 정적 코드 검토이며 실행 기반 채점과 합산하지 않는다. AI 제안과 교수자 확정은 다른 필드와 상태로 보관한다.
