# 실습 채점 시스템 구현 계획 및 현재 상태

갱신일: 2026-10-26. [이전 설계안](design-plan-2026-09-11.md)은 별도로 보존한다.
이 문서는 현재 작업 트리 기준이며, 기존 변경 사항과 이번 핵심 기능 구현을 함께 반영한다.

2026-10-26 정리:
- 저장소 동기화는 전체·성공·실패 인원을 집계하고 실패 학생의 이름·학번·사유를 표시한다. CSV 검증 오류는 동기화 시작 실패로 구분한다.
- LLM 서버 주소와 모델명은 코드에 포함하지 않고 환경 변수, 화면 저장 설정, `settings.local.json`에서 읽는다. 설정 누락·오류를 화면에서 안내한다.
- 로컬 설정, 학생 명단·저장소, 실행 결과, 강의 원본과 추출 카탈로그를 새 커밋 및 Docker 빌드 대상에서 제외한다. 기존에 추적된 명단 이력은 유지한다.
- 변경 이력을 채점 엔진, 저장소 동기화, 케이스 보강, AI 평가·외부 설정, 화면, 문서 단위로 분리한다.

## 사용 흐름 수정 (2026-10-14)

2026-10-16 점검·수정: 슬라이드 제목/본문 검색, 다중 선택, 같은 문제 페이지 일괄 선택과 텍스트 미리보기를 AI 케이스 생성·정성평가에 공통 적용했다. PPT 내부 파일 번호가 아닌 실제 발표 순서로 페이지를 읽는다. 이미지가 있는 페이지는 원본 확인을 표시하며 OCR은 수행하지 않는다. 서로 다른 문제를 함께 선택하면 가져오기를 막는다.

생성 대상 장·문제·저장 경로를 상단에 표시하고 원본 페이지와 대상을 생성 기록에 저장한다. 생성 후 대상/설명/원본을 바꾼 상태로 저장하는 것을 막고, 기준 코드 변경 시 검증을 해제한다. 메인 문제 목록은 활성 케이스, 초안, 케이스 없음 순으로 표시하며 학생 제출과 별개로 케이스 폴더를 검색한다. 새 저장 결과가 문제 목록에 즉시 반영된다. 표준출력과 파일 기대값을 함께 표시하며 전체 상세 내용을 열 수 있다. 밑줄이 포함된 과목 이름이 잘리는 경로 처리도 수정했다.

기본 화면의 채점을 중심으로 AI 생성과 실행을 연결한다.
**AI 케이스 생성 → 기준 코드 검증 또는 직접 검토 → 채점에 추가 → 채점 시작 → 결과 자동 저장**이 일반 사용 경로다.
메인 화면에서 활성 케이스 수와 자동 저장 위치를 보여 준다.
`reports/case-grading/<실행시각_식별자>/`의 `run.json`, `cases.csv`, `summary.csv`에 학생별 완료 결과를 저장한다.
판정은 통과/실패와 통과 수이며, 무배점 케이스에 임의의 점수를 계산하지 않는다.
이전에 주 화면에 노출한 “문제 기반 채점”은 **고급 → 명세 파일로 배점 채점…**으로 옮겼다.
아래 K1–K7은 명세·배점이 필요한 고급 경로의 구현 상태다. 일반 AI 케이스 사용의 전제 조건이 아니다.

## 일괄 채점 화면 개선 (2026-10-14)

- 분반·문제 선택, 대상 학생 선택, 일괄 실행의 세 영역으로 주 화면을 재구성했다.
- 분반 선택 시 전체 학생을 기본 선택하고, 전체 선택/선택 해제와 클릭 토글을 제공한다.
- 학생을 제외해도 문제 선택은 바뀌지 않는다. 장/문제 목록은 분반 전체 제출물을 기준으로 모은다.
- 버튼에 실제 선택 인원을 표시하고, 실행 전 학생 수·케이스 수·문제·환경을 함께 보여 준다.
- 결과는 학생별 표로 표시하고 완료할 때마다 갱신한다. 중지는 현재 학생을 저장한 뒤 적용한다.
- 공통 글자는 기본 12pt이며, 14pt·16pt 확대와 설정 보존을 지원한다.
- 코드 확인과 직접 실행은 별도 탭으로, 실행 환경과 보조 기능은 도구 메뉴로 옮겼다.
- 기본 1440×960 화면과 16pt의 1280×800 화면을 렌더링해 실행 버튼과 선택 도구가 잘리지 않는지 확인했다.

## 1. 제품의 중심

2026-10-14 추가 보강: AI 기대값의 미검증/수동 검토/기준 코드 검증을 구분한다. 기준 코드를 두 번 실행하여 기대값을 교정하고 비결정적 출력과 예기치 않은 종료를 거부한다. 제공한 오답 예제가 모두 통과하면 검사 누락으로 저장을 막는다. 편집 시 검증을 해제하며, 동일 케이스를 다시 저장해도 개수가 늘지 않는다. 최장 줄 예제의 중복을 제외하고 10개로 보강했으며 오답 예제 3종을 탐지했다.

메인 화면에서 시스템 설정/라이트/다크 모드를 선택하고 저장한다. 시스템 설정에서는 Windows의 모드 변경을 따라가며 수동 선택은 유지한다. 일반 QWidget 창, 입력칸, 선택 항목, 비활성 상태와 콤보 팝업까지 모드별 배경·글자색을 함께 지정한다. 두 모드의 글자 대비, 열린 창에 즉시 반영, 설정 복원과 화면 렌더링을 확인했다.

조교가 문제와 배점을 정의하고, 학생 제출물을 확정한 뒤, 격리된 복사본에서 채점하여
근거가 남는 성적표를 만드는 데 집중한다.

명세를 쓰는 고급 흐름은 **문제 선택 → 명세 검증 → 제출물 확인/경로 지정 → 배점 채점 → 근거 검토 → 최종 점수 저장**이다.
PPT 조회, AI 케이스 생성, Qwen 정성평가는 보조 도구로 유지한다.
AI 정성평가 점수는 실행 기반 점수와 자동 합산하지 않는다.

## 2. 기존 코드에서 재사용한 부분

- CSV 명단 읽기와 Git 제출물 수집: `evaluator.py`, `gitmanager.py`.
- C/Python 실행, Docker 제한, 케이스별 작업 사본, stdout/stderr/파일 검사: `grader.py`.
- 자료 조회, AI 기능, 기존 케이스 생성 및 내보내기.

기존 `testcase` 자료와 조교의 작업을 보존하기 위해 기존 실행 경로를 유지한다.
이전 계획의 “호환 코드 없이 전체 이관” 방침은 실제 운영 자료가 늘어난 현황을 고려해 변경한다.
새로운 성적 산출은 `problem.yaml`을 사용하며, 기존 케이스 실행은 무배점 결과 확인용이다.

## 3. 핵심 기능과 구현 상태

| K2 제출물 확정 | 후보 순서 탐색, 미확정 사유, 학생별 경로 보정 저장 | `core/resolver.py` | 구현 |
| K3 실행 | 환경 사전 검사, 제출물/케이스 사본, 이미지 ID 고정, 제한 시간 | `core/service.py`, `grader.py` | 구현 |
| K4 점수 산출 | 완전일치/공백 정리/토큰/수치 비교, 케이스별 배점 합산 | `core/service.py`, `grader.py` | 구현 |
| K5 기록 | 학생별 완료 시 자동 저장, JSON 원장, CSV 성적표, 입력·제출물 스냅샷 | `core/record.py` | 구현 |

## 4. 계약과 판정 원칙

- 문제 파일: `assignments/<분류>/.../problem.yaml`, 버전 1.
- 케이스: 명세 옆 `cases/<이름>/`의 `stdin.txt`, `expected.txt`, `args.txt`, 선택적 `case.yaml`, `files/`.
- 매핑: 기본 `layout.local.yaml`; CLI에서는 `--layout`으로 다른 파일을 선택할 수 있다.
- 기록: `records/<문제ID>/<실행ID>/run.json`, `summary.csv`, `inputs/`, `submissions/`.
- 배점 합 불일치, 없는 케이스, 검사 항목 부재, 잘못된 경로·명세는 실행 전에 거부한다.
- 경로/파일 후보는 선언 순서가 우선이다. 학생별 보정이 있으면 그것만 사용한다.
- 미확정·채점기 오류·미실행은 점수가 `null`이다. 오답/컴파일 오류/실행 오류/시간 초과는 해당 케이스 0점이다.
- 실행 환경 오류는 배치 시작 전에 검사한다. 학생별 예외는 다음 학생 처리를 막지 않는다.
- 학생별 기록은 원자적으로 교체한다. CSV는 JSON에서 다시 생성할 수 있는 파생 산출물이다.
- 기록 저장 실패는 정상 완료로 처리하지 않는다. 중지 시 완료 학생을 보존하고 나머지는 미실행으로 남긴다.
- 점수 조정은 자동 점수를 유지하고 최종 점수와 조정 이력에만 반영한다.

## 5. 검증

2026-10-14 최종 검증: Docker 통합 검증을 켠 전체 69개 테스트 통과(건너뜀 없음).
AI 케이스 활성 저장 → 메인 화면 채점 → 자동 저장 → 재열기를 Windows와 Docker에서 검증했다.
GUI 화면을 가상 제출물로 렌더링해 점수·미확정 상태·케이스 근거 배치를 확인했다.

`tests/test_core.py`: 배점 계산, 미확정 공란, 잘못된 명세, 후보/보정 경로,
입력 스냅샷, 원본 보존, 수동 점수 이력, 중지, 환경 오류, 학생별 실패 격리, CLI.
`tests/test_gui.py`: 비동기 채점 후 저장·수동 점수 조정·기록 재열기.
Docker 통합 검증: 이관한 C 파일 복사 문제와 기존 복수 소스 링크·컴파일 오류·표준입력·시간 초과 정리.

예제 기대 결과: `demo_good` 10/10, `demo_partial` 6/10, `demo_missing` 미확정/점수 공란.
기존 C 파일 복사 예제는 4개 케이스를 통과해 10/10이다.
실제 학생 성적을 확정하는 검증은 수행하지 않는다.

## 6. 운영 적용을 위해 남은 작업

1. **실제 문제별 지문·배점 승인과 이관**: 현재 합계 예제와 파일 복사 예시를 제공한다.
   파일 복사의 10점은 검증용 배점이며 실제 교수자 배점으로 간주하지 않는다.
2. **분반별 매핑 확정**: 실제 명단 전체와 저장소를 대조하는 작업은 별도로 필요하다.
   명단 기준 대상 선택 또는 CLI --roster로 폴더가 없는 학생까지 미확정 목록에 포함할 수 있다.
3. **기한 정책**: `due`가 있으면 변경 없는 저장소의 최신 커밋 시각으로 지연 시간을 기록한다.
   커밋 시각은 서버 제출 시각과 다르며, 자동 감점이나 마감 당시 커밋 체크아웃은 아직 하지 않는다.
4. **운영 환경 확대**: Windows와 Docker를 검증한다. 네이티브 Linux/WSL의 실제 통합 검증은 남아 있다.
5. **개인정보 관리**: 신규 명단·DB·기록·로컬 매핑에 무시 규칙을 추가했다.
   기존에 추적 중인 명단/DB 및 원격 이력은 이번에 삭제하거나 재작성하지 않았다.
6. **규모 확장**: 전체 학기 합산 성적표, 장기간 기록 보존/정리, 다중 조교 동시 편집은 후속 범위다.

## 7. 개발 우선순위

다음 개발은 실제 수업의 문제·배점 계약을 확정하고 한 분반의 제출물 매핑을 완료하는 데 우선한다.
그 후 학기 성적표 합산과 마감 정책을 연결한다. 웹 서비스화, 표절 검사, AI 기능 확대는 그 뒤로 둔다.

명세 형식과 실행 예시는 [문제 기반 채점 사용법](manifest-grading.md)을 따른다.
