실행 환경

같은 코드, 네 가지 다른 결과

네 환경은 서로 다른 명령을 만들고 서로 다른 정리 동작을 합니다. 문제는 이 차이가 채점 결과를 바꾼다는 점입니다. 수학 함수를 쓰는 정상적인 C 코드는 컨테이너와 리눅스에서 링크에 실패하지만 Windows에서는 통과합니다.

프로세스 실행 방식

출력을 파이프가 아닌 임시 파일로 받아 제한 시간을 거는 구조라 출력이 많을 때 생기는 교착이 원천적으로 없습니다. 실측에서 5.4 GiB를 뱉는 프로그램에도 정확히 10초에 끊겼습니다. 채점기를 처음 만들 때 가장 흔히 밟는 함정을 피했습니다.

줄바꿈 정규화

출력 비교 전에 줄바꿈을 통일하고 테스트케이스도 텍스트 모드로 읽습니다. Windows와 리눅스가 섞인 환경에서 가장 흔한 오채점 원인 하나가 막혀 있습니다.

계층 분리

실행기가 화면 요소에 의존하지 않아 화면 없이 불러 검증할 수 있습니다. 회귀 테스트를 붙이기 쉬운 형태라는 점이 실질적인 자산입니다.

정답을 직접 실행해 만드는 케이스 생성

기대 출력을 손으로 적는 대신 정답 코드를 실제로 돌려 만들고, 그 실행에 채점기와 같은 실행기를 재사용합니다. 생성 경로와 채점 경로의 동작을 일치시키려는 의도가 분명합니다.

컨테이너를 기본값으로

격리를 지향한 방향 자체는 옳고, 이미지도 최소한으로 유지되어 있습니다. 컨테이너 쪽은 한글 출력 인코딩 문제에서도 자유롭습니다.
